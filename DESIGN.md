# spacekit: design

## Model
- **Display:** a screen attached to the Mac, known by its UUID. It has user spaces in Mission Control order, shows one space at a time, and has a visible frame, the part under the menu bar and beside the Dock that its windows may occupy. Fullscreen spaces sit in the same order, after the user spaces.
- **Space:** a Mission Control desktop on one display, known by its UUID, or by its display and position for the desktop that has no UUID; when its UUID is gone it is found again by display and position. A fullscreen space holds one fullscreen window and is never a target for a move.
- **Space switch:** steps one display to the adjacent space with the native slide, by posting Ctrl+Left or Ctrl+Right as a hardware keystroke, which Mission Control accepts where a shortcut posted from an ordinary process is ignored. It acts on the display under the pointer; a switch the agent makes moves the pointer to that display for about a tenth of a second and back. A one-shot switch waits up to 1.5 s for the active space to change, since a process that exits at once loses the keystroke.
- **Tilt:** a click of a mouse's tilt wheel, a single discrete scroll event that is horizontal only. The spaceswitch daemon consumes it and switches space, left tilt to the previous space unless inverted. Vertical scrolling, continuous scrolling from a trackpad or Magic Mouse, and shift-wheel horizontal scrolling pass through untouched.
- **App:** the owner of windows, known by its bundle identifier, or by its name when it has none.
- **Window:** a lasting identity for one of an app's windows, across relaunches, logins and reboots. It has a title, a binding in each login session it has been seen in (the latest one is how it is known on screen), and a target in each arrangement it has been seen in. Only a placeable window is kept: an ordinary visible window at least 50 points on each side, attached to no parent and not the window manager's own, that is on one user space, or fullscreen with a title.
- **Binding:** the window-server id a window carries in one login session, from login to logout or shutdown, since the window server reuses ids across the logins of one boot. It is dead once that id is absent from the whole window list; a minimized window stays listed. A fresh window is bound to a stored window of the same app only on unambiguous evidence: one candidate for the fresh window and one fresh window for that candidate. Evidence is settled strongest first: same title and frame, then same frame alone, then same title, then the same app alone, which counts only for a fresh window that is its app's only fresh one. Titles are compared with unread counts removed and an empty title matches nothing; frame evidence comes only from a target in the arrangement being decided, and a fullscreen window offers none. Candidates tied at any level narrow to the one bound in the latest login session; twins bound in the same login session stay ambiguous, and a fresh window whose strongest evidence is ambiguous binds to nothing weaker. A window without such evidence is a new window, since a wrong binding moves an unrelated window and a missed one only leaves a window where its app put it.
- **Arrangement:** the targets for one display set, the displays present at once. Each display set has its own arrangement, so the laptop alone and the laptop with an external display keep separate targets, and an arrangement returns when its displays do. It records the spaces it has had.
- **Target:** where a window belongs in an arrangement: a space and a frame, or fullscreen on a display. A window is at its target when it is fullscreen on the same display, or on the same space with every edge within 3 points. Targets are versioned: each keeps the period in which it held, and versions closed more than 90 days ago are deleted, with windows not bound since then.
- **Current:** the agent's picture of the login session: the displays, the space each shows, and each window's space or fullscreen display and its frame. It is seeded by one read at startup and then kept from the window server's events, each followed by a read of that window's frame; a window between a detach and its attach is in transit, held but not decided. Once a minute a full read validates it: each difference is logged and taken into Current only when two consecutive reads agree on it, and a read taken while Mission Control or Exposé is showing compares nothing.
- **Decide:** compares windows in Current with their targets. It runs when a window's events have settled for 500 ms, when a display change has settled for 10 s, at startup, when a put ends, and on the minute tick for windows marked dirty with no put tried. It waits while the login session is locked, asleep or powering off, while a display change runs and while a put runs, and is taken when the wait ends. A window with no record or no target is adopted where it is. A window off its target for a system cause is dirty and put back; one off its target for any other cause moved for the user, and its target follows it.
- **System cause:** a display change and the 20 s after it settles, a window bound to its record in this decide, and the agent's own put within 2 s of its end. Any other change to a window is the user's.
- **Dirty window:** a window owed a put back to its target in an arrangement, recording whether a put has been attempted. A window is marked dirty by a system cause, by `owe` (every window on screen with a target), or by `undo`. It is clean again once it is at its target. A put that was attempted and did not take is a failed put: the target stays, and the window is put again at the next display settle. A put attempt is recorded on the binding it was tried on, so a fresh binding has none and a window newly bound to a record is put at its first decide, whatever an earlier binding's put did.
- **Put:** carries dirty windows to their targets in confirmed steps: a window on a hidden space is staged to the space its display shows, resized through Accessibility, and sent home. Each step is confirmed by the screen's own events within 2 s, and a required step left unconfirmed ends that window's sequence. A fullscreen target is restored by staging the window to its display's shown space, giving it the display's visible frame, setting it fullscreen, and stepping the display back to the space it showed; a failed return leaves the display on the fullscreen space. A window fullscreen away from its target is first taken out of fullscreen: its display is stepped to the fullscreen space, AXFullScreen is cleared, and the window's attach to a user space with the display leaving the fullscreen space confirms it; it is then put as any window, and the display is stepped back last when it showed a user space and the put was not cancelled. A put with nothing it can order is a failed put.
- **Change:** one decide, binding or undo that altered the record, with its time and cause, and per window what it did: adopted, bound, dirty, put, clean, failed or undone. `log` lists changes; `undo` reverts the targets one change opened that are still current, restoring the targets it closed, and marks those windows dirty.
- **Event stream:** every event the agent sees, from the window server, the system and its own processes, journaled and kept for seven days; `log -events` reads it back.

## Tests
- Pending mark: `pending(t)`, called first in a model-level test, skips it unless `RUN_PENDING=1` is in the environment; it is defined in `pending_test.go` in each package with model-level tests (`cmd/spacekeeper` and each tested package under `internal/`).
- Model-level tests are every existing `*_test.go` in `cmd/spacekeeper` and `internal/`, run with `make test` (`go test ./...`). The `cmd/spacekeeper` tests run the agent's processes on a bus against a scripted window server (`fakeReader`, `fakeOrders`) and a temporary store; the `internal/skylight` tests other than `TestServerFrameFlipsAppKitRectangles` read this Mac's window server and displays. `cmd/spaceswitch` has no tests. A unit test below a domain object's interface goes beside the code in `*_unit_test.go`.
